# Argo CD deployment (M5)

The Application is `modelgate`, stored in `argocd/application.yaml`. It follows
`https://github.com/berikbp/modelgate`, branch `main`, path `k8s`, and deploys
into `default`. Both the Deployment and Service are named `modelgate`.

## Prerequisites

M4 must be merged on GitHub, Docker must be running with WSL integration enabled
on Windows, and the intended Kubernetes context must be selected. Check before
changing the cluster:

```bash
kubectl config current-context
kubectl get nodes
kubectl -n default get secret app-secret -o name
```

The node must be Ready. The Deployment reads key `API_KEY` from `app-secret`.
Keep the existing Secret. On a fresh lab cluster only, create it if absent:

```bash
kubectl -n default create secret generic app-secret --from-literal="API_KEY=$(openssl rand -hex 16)"
```

## Install Argo CD 3.5.3 (Path B, core)

The core install supports the whole lab through kubectl and needs less memory
than the full installation. Download outside the repository and verify the
lab's exact checksum before applying:

```bash
kubectl create namespace argocd --dry-run=client -o yaml | kubectl apply -f -
curl -fsSLo /tmp/modelgate-argocd-core.yaml https://raw.githubusercontent.com/argoproj/argo-cd/v3.5.3/manifests/core-install.yaml
echo '1a87025d8eb2eae621653fd312fb9ca51df1b4b3b6992a030e3a9ef38e45c448  /tmp/modelgate-argocd-core.yaml' | sha256sum -c - && \
  kubectl apply -n argocd --server-side --force-conflicts -f /tmp/modelgate-argocd-core.yaml
kubectl -n argocd wait --for=condition=Ready pods --all --timeout=600s
kubectl -n argocd get pods
kubectl get crd applications.argoproj.io applicationsets.argoproj.io appprojects.argoproj.io
```

Do not apply a manifest that fails its checksum. Core has no web UI.

On the fresh core installation used for this lab, the `default` AppProject did
not exist. The Application reported `InvalidSpecError: Application referencing
project default which does not exist`. Before handing over the service, check
for it and create the supplied project if missing:

```bash
kubectl -n argocd get appproject default
# Only if it is absent:
kubectl apply -f argocd/project.yaml
```

This project permits this repository, the `default` destination namespace, and
the three resource kinds in `k8s/`. It stays outside `k8s/`; the official marker
creates its own project and reads only our Application's source and sync policy.

## Hand over the existing M4 service

Merge the Application into `main` first. Deleting the M4 objects briefly
interrupts the service; it leaves `app-secret` alone because it is outside `k8s/`.

```bash
git switch main
git pull --ff-only
kubectl -n default delete -f k8s/
kubectl apply -f argocd/application.yaml
kubectl -n argocd get application modelgate -w
```

Wait for both `Synced` and `Healthy`, then check the service:

```bash
kubectl -n default rollout status deployment/modelgate --timeout=300s
kubectl -n default get --raw /api/v1/namespaces/default/services/modelgate:80/proxy/healthz
kubectl -n default get secret app-secret -o name
```

## Demonstrate self-heal

Predict that Argo CD will restore the two replicas declared in Git, then run:

```bash
kubectl -n default scale deployment/modelgate --replicas=5
kubectl -n default get deployment modelgate -w
```

Stop watching after the replica count returns to two. Test Service recovery:

```bash
kubectl -n default delete service modelgate
kubectl -n default get service modelgate -w
```

Argo CD recreates it from Git. Change the manifests and merge a commit to make
a persistent change. `prune` removes managed resources no longer in Git;
`selfHeal` repairs drift in resources still in Git.

## Deploy a new image and roll back

Find the full SHA of a successful CI publish on `main`. Change only the image
tag in `k8s/deployment.yaml` to that SHA on a new branch, commit, push, and merge
a pull request. Confirm that the published package is publicly pullable.

```bash
kubectl -n argocd annotate application modelgate argocd.argoproj.io/refresh=normal --overwrite
kubectl -n argocd get application modelgate -w
kubectl -n default get deployment modelgate -o jsonpath='{..image}'; echo
```

Wait until the live image matches the new SHA. Follow the README's Rollback
section to revert the image-bump commit, push the revert, refresh, and confirm
that the old image returns. A successful rollout command alone does not prove
Argo CD has fetched the new commit; inspect its revision and the live image.

## Mark the submission

The marker is downloaded locally and excluded through `.git/info/exclude`:

```bash
curl -fsSLo mark_m5.py https://raw.githubusercontent.com/inf345/inf345-week10-lab/main/mark_m5.py
python3 mark_m5.py --path .
python3 mark_m5.py --path . --kind
```

The live command creates its own cluster, `inf345-m5`. It does not use the lab
cluster. Push committed changes first, since Argo CD fetches from GitHub.
Alternatively, `.github/workflows/m5.yml` runs the lab's supplied live check
on pull requests or through Actions → M5 check → Run workflow.

The workflow uses checksum-pinned kubectl 1.36.1. With the example workflow's
1.37.1 client, two GitHub runs reported `NOT CHECKED` because the CRD wait
failed with `.status.conditions accessor error: <nil> is of the type <nil>,
expected []interface{}`. The 1.36.1 client passed the complete unmodified marker
locally against its Kubernetes 1.36.4 cluster.

Static success does not prove sync or healing. The complete live result must
say `SCORE: 100/100`. For failures, inspect:

```bash
kubectl -n argocd get application modelgate -o yaml
kubectl -n default get pods
kubectl -n default describe pods
kubectl -n default get events --sort-by=.lastTimestamp
```
