# Kubernetes deployment

The deployment uses the existing public M3 image
`ghcr.io/berikbp/modelgate:93482e37dbf9772a45879053cb8cd8f17342c3ea`.
Its Dockerfile runs as user `10001:10001` and starts Uvicorn on `0.0.0.0`,
reading `PORT` from the environment.

## Deploy

Create the Secret on your cluster, then apply the three manifests:

```bash
kubectl create secret generic app-secret --from-literal="API_KEY=$(openssl rand -hex 16)"
kubectl apply --dry-run=server -f k8s/
kubectl apply -f k8s/
kubectl rollout status deployment/modelgate --timeout=180s
kubectl port-forward service/modelgate 8080:80
```

In another terminal:

```bash
curl -i http://localhost:8080/healthz
```

The expected response is HTTP 200 with `{"status":"healthy"}`.
Create `app-secret` in the same namespace as the Deployment. Its value is generated
locally; no Secret object or credential belongs in the repository.

## Configuration and probes

- `PORT` comes from `modelgate-config` and is read by the image's startup command.
- `UVICORN_LOG_LEVEL` comes from the same ConfigMap. Uvicorn's CLI reads it using
  its `UVICORN` environment prefix and applies it to the server's logging. For
  example, `warning` suppresses informational access and startup logs. This works
  in the pinned M3 image without rebuilding application code.
- `API_KEY` is injected from key `API_KEY` of `app-secret`. The current mock API
  does not require authentication; injecting the Secret does not add API authentication.
- The Service selects `app: modelgate` and routes port 80 to the named `http`
  container port, 8080.
- Both probes request `/healthz` through `http`. Readiness uses 5 seconds times
  3 failures (15 seconds); liveness uses 10 seconds times 3 failures (30 seconds).
  Readiness removes an unhealthy Pod from traffic before liveness restarts it.
- Each replica requests 50m CPU and 64Mi memory, with limits of 250m and 128Mi.
  The container has a read-only root filesystem and a writable `/tmp` volume.

Environment variables are loaded when a container starts. After changing the
ConfigMap, apply it and restart the Deployment:

```bash
kubectl apply -f k8s/configmap.yaml
kubectl rollout restart deployment/modelgate
kubectl rollout status deployment/modelgate --timeout=180s
```

When changing `PORT`, also update `containerPort` in the Deployment; the Service
and probes use the named port and follow that value.

## Official marker

Download the marker without committing it:

```bash
curl -fsSLo /tmp/modelgate-mark_m4.py https://raw.githubusercontent.com/inf345/inf345-week9-lab/main/mark_m4.py
python3 /tmp/modelgate-mark_m4.py --path .
python3 /tmp/modelgate-mark_m4.py --path . --kind
```

The static run checks the files. The live run uses a separate temporary kind
cluster and must report `SCORE: 100/100`, including readiness removal, liveness
restart, and deployment with a random `PORT` and a new random Secret value.
The GitHub Kubernetes workflow runs these checks for pull requests as well.
